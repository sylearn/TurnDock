# 回合 · TurnDock

一个本地优先的 AI 请求收件箱。让每次确认有上下文，让回复有去向，让等待保持安静。

**当前阶段：产品定义、技术设计与可操作视觉原型。尚未实现正式桌面程序、MCP 服务或安装包。**

源于对 [寸止](https://github.com/imhuso/cunzhi) 的使用与源码审查，采用独立实现路线，不在旧项目上叠加补丁。名称暂定为回合 / TurnDock，发布前检查名称、包名和商标冲突。本轮没有新建公开仓库，也没有替换本机寸止。

## 先看什么

1. 打开 [交互原型](design/prototype/index.html)：直接用浏览器打开即可；全部为本地演示数据，不连接 AI。
2. 阅读 [产品定义](docs/01-产品定义.md)：保留哪些核心能力、哪些先不做。
3. 阅读 [视觉与交互](docs/02-视觉与交互.md)：排版、色彩、完整操作与异常状态。
4. 阅读 [技术架构](docs/03-技术架构.md) 和 [协议与数据](docs/04-协议与数据.md)：常驻进程、等待、取消、投递、安全边界。
5. 按 [实施路线](docs/05-实施路线.md) 逐关开发，并使用 [验收标准](docs/06-验收标准.md) 判断是否完成。
6. 查看 [寸止审查依据](docs/07-寸止审查依据.md) 和 [本轮验证记录](docs/08-本轮验证记录.md)，区分实测、静态推断、未来目标。

## 已确定的方向

- Rust + Tauri 2 + Vue 3 + 严格 TypeScript；前端定制设计，不照搬通用后台组件外观。
- 一个常驻桌面应用管理队列；每个 MCP 客户端只启动轻量 stdio 桥接器，不为每条请求启动一个新桌面进程。
- 本地数据库集中管理请求和草稿；凭据进入系统凭据库。默认没有云同步、遥测或外部内容请求。
- 先做好「提问 → 安静等待 → 明确回复 → 可核查投递」这一条链路，再考虑远程通知和其他扩展。
- macOS 首发验证，核心协议与存储保持跨平台；Windows/Linux 的平台适配经过真实设备验证后再宣称支持。

## 开发起点

下一步从路线的 M0 开始：建立可取消的协议状态机与假客户端测试，随后把最小真实请求接入桌面窗口。不要先扩展设置面板或安装包，也不要把浏览器原型当成生产代码直接搬入。

原型无需 npm install；正式工程的依赖锁定、workspace 和 CI 在 M0 创建。当前目录刻意不提供不能运行的 Rust/Vue 空壳。
