# 01 · 产品定义

## 一句话

回合（TurnDock）是你和 AI 之间的交接点：AI 每做完一轮工作，就把成果、验证情况和建议的下一步交给你。你一眼看懂，一键定下方向，然后顺着往下做。

## 为什么重新定位（2026-10-20）

寸止诞生时有两个前提：按请求计费，所以“别让 AI 提前结束”能省钱；AI 缺少记忆和代码检索，所以要内建这些能力。这两个前提都已经不成立：

- 主流 AI 客户端不再按请求计费；
- 记忆、代码检索有成熟的 skill 与专用 MCP，客户端自己也在做。

现在稀缺的是**人的注意力和判断**。AI 一跑几十分钟，几个项目同时推进。每一轮结束时，终端里留下一大段文字，你要自己从中找出：它做完了什么、哪些真的验证过、哪里有风险、接下来该干什么。建议埋在最后几行，换个项目回来，思路就断了。

回合解决的就是这个“交接”：让每一轮的结束变成一个清楚的决策点。

## 三类请求

| | 回合交接 `hand_off`（主场景） | 中途决策 `ask_user` | 寸止兼容 `zhi` |
|---|---|---|---|
| 何时 | 做了实际工作的一轮结束前 | 工作中遇到多个方案、需求不明、有影响的操作 | 沿用寸止规则的旧配置 |
| 内容 | 标题、做了什么、验证情况、风险、2–4 个建议的下一步（一个推荐） | 问题、上下文、选项（可标推荐） | 消息与预设选项（多选） |
| 你通常做什么 | 看验证，按 ⌘↵ 接受推荐；或换一个方向、补一句要求 | 选一个方案，或补充信息 | 选择或写回复 |

纯问答不需要交接，避免小事也打扰你。

## 交接的质量从哪里来

回合**不调用任何模型**。客户端里的 AI 才有完整上下文，再调一次模型既重复，又涉及隐私和成本。回合负责的是：

1. **协议逼出好交接**：`hand_off` 的字段要求 AI 区分已验证与未验证（passed / failed / not_run / manual），列出风险，给出具体可执行的下一步并说明理由与代价，恰好一个推荐。
2. **界面让判断变快**：先看结果与验证，再看风险，然后是下一步（推荐项预选），最后才是细节。
3. **规则片段**：给 AI 的规则写明何时交接、怎样写好交接，不允许“继续优化”这类空话。

## 与宿主自带能力的区别

MCP elicitation 与宿主原生提问都能问用户，但做不到：

- **跨项目、跨宿主的统一交接台**：Claude Code、Codex、Cursor 的交接在同一处，标明来源与项目，你决定先把注意力给谁。
- **结构化的交接**：验证状态、风险、推荐与理由，而不是一段自由文本。
- **可离开的长等待**：请求独立于单次工具调用，宿主超时、应用重启都不会丢。
- **决策记录**：每一轮选了什么方向、为什么，按项目可回看。

## 能力与取舍

| 能力 | 决策 | 状态 |
|---|---|---|
| `hand_off` 回合交接 | 主场景；推荐项预选，⌘↵ 接受 | 已实现 |
| `ask_user` 中途决策 | 单选/多选/文字/图片，可标推荐 | 已实现 |
| `await_reply` 续等 | 宿主超时前返回 pending，AI 凭 request_id 继续等 | 已实现 |
| `zhi` 兼容 | 参数与回复格式与寸止一致 | 已实现 |
| 草稿、图片回复、拒绝/先停下、关闭 | — | 已实现 |
| 快捷回复 | 用于提问类请求；交接中隐藏，避免与推荐项重复 | 已实现 |
| 决策记录视图（按项目时间线） | 已处理列表是基础；按项目分组与回看 | M2 |
| Claude Code Stop hook 适配 | AI 想停止时确定性地要求交接，不依赖模型自觉 | M5 评估 |
| 内建模型、记忆、代码检索 | 不做 | — |
| 隐藏的增强提示词、自动继续 | 不做；方向必须由你可见地决定 | — |

## 不变的原则

1. **沉默不是同意。** 超时、断线、取消、关闭窗口、关闭请求，都不能让 AI 理解为同意或继续。
2. **回复不错投。** 一条回复只交给持有该请求的调用；跨会话领取必须由 AI 显式提供 request_id。
3. **状态如实。** “已交给连接”不等于“AI 已执行”；未验证的就标未验证。
4. **本地优先。** 没有账号、云同步、遥测或外部内容请求。
5. **不打扰。** 默认一次通知、不抢焦点；纯问答不交接。

## 完成标准（用户视角）

| 场景 | 必须做到 |
|---|---|
| 一轮工作结束 | 不滚动就能看到结果、验证、风险与推荐的下一步；同意推荐只需一次 ⌘↵ |
| 想换个方向 | 数字键选另一个下一步，或直接写新指示 |
| 三个项目同时交接 | 三条可区分的请求；切换不丢草稿；回复只到对应调用 |
| 离开一小时再回来 | 在 Codex 默认 60 秒超时下，请求仍在，回复后 AI 能拿到 |
| 应用重启 | 正在等待的 AI 自动重连续等，无需任何操作 |
| 我要它先停下 | 需要确认；AI 收到的是明确的“先停下”，不是错误 |
| 中文输入法按回车 | 只确认候选字，不发送 |
