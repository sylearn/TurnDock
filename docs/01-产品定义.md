# 01 · 产品定义

## 一句话

回合（TurnDock）让 AI 的一轮工作在需要你时停下来等你，而不是自作主张或提前结束；你可以在任何一个 AI 客户端、任何时间、用最少的动作给出回复。

## 两类场景

| | A · 回合检查点（高频） | B · 决策请求（低频） |
|---|---|---|
| 何时出现 | AI 完成一段工作、准备结束本轮之前 | 有多个方案、需求不明确、即将做有影响的操作 |
| 你通常回什么 | “继续”“接下来做 X”“先停下总结”，短文字 | 选一个方案、补充材料、贴截图、拒绝 |
| 体验要求 | 两三秒内完成：唤出 → 一个键 → 发出 | 能看清上下文，长消息好读，草稿不丢 |
| 入口 | 快速回复面板 | 完整收件箱 |

寸止被广泛使用的根本原因是 A：AI 每轮结束前都会来问，在按请求计费的客户端里还能在一次请求内完成多轮协作。B 是在 A 的基础上把“问人”做得更可靠。**A 必须是最快路径**，任何设计不能让 A 变慢。

## 与宿主自带能力的区别

MCP elicitation 与 Claude Code 等宿主的原生提问都能问用户。回合的价值在于它们做不到的部分：

- **跨宿主统一队列**：Claude Code、Codex、Cursor 的请求在同一处，标明来源和项目。
- **可离开的长等待**：请求的生命周期独立于单次工具调用，宿主超时不会丢失请求或回复（见 04）。
- **完整的回复**：图片、多选、自由文本、快捷回复、草稿与历史。
- **一致的体验**：不依赖每个宿主的提问 UI 质量。

宿主原生提问已经够用的场景，用户不必使用回合，两者可以共存。

## 核心能力

| 能力 | 决策 | 阶段 |

| 快捷回复 | 用户可见、可编辑（如“继续”“按最佳实践继续”），发出的就是看到的文字 | M1 |
| 明确拒绝 | 独立动作，AI 收到明确的否定结果 | M1 |
| 草稿 | 按请求保存，切换、重启后都还在 | M2 |
| 图片回复 | 粘贴/拖放/选择，按文件签名校验真实类型 | M2 |

## 不变的原则

1. **沉默不是同意。** 超时、断线、取消、关闭窗口、用户关闭请求，都不能让 AI 理解为同意或继续。
2. **回复不错投。** 一条回复只交给持有该请求的调用；跨会话领取必须由 AI 显式提供 request_id。
3. **状态如实。** 没有证据时不显示“已送达”；“已交给连接”和“AI 已执行”是两回事。
4. **本地优先。** 没有账号、云同步、遥测或任何外部内容请求。
5. **不打扰。** 默认不抢焦点、不置顶、不重复提醒；用户可为特定宿主开启弹出。

## 完成标准（用户视角）

| 场景 | 必须做到 |
|---|---|
| 回合检查点 | 从通知/快捷键到发出“继续”，不超过 3 次按键 |
| 三个项目同时问 | 三条可区分的请求；切换不丢草稿；回复只到对应调用 |
| 离开一小时再回来 | 在 Codex 默认 60 秒超时下，请求仍在，回复后 AI 能拿到 |
| 我不允许 | 拒绝需要确认，AI 收到的是明确的否定，不是错误 |
| 发出时 AI 已经断开 | 不显示“已送达”；回复保存为“等待领取” |
| 中文输入法按回车 | 只确认候选字，不发送 |
| 粘两张图删第一张 | 剩下第二张，类型与字节不变 |
