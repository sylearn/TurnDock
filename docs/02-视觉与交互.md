# 回合 TurnDock · 视觉与交互规格

状态：第一版设计方案，2026-10-20。交互原型是验证方向的样本，不代表桌面程序已实现。

## 1. 设计立场

这是人给 AI 回应的地方，不是另一个聊天客户端。安静、看得清、不会误操作，比界面炫技重要。视觉记忆点放在「回合标记」和清晰的回复工作区，其他元素保持克制。

初稿比较过三种布局：居中弹窗最简单，但多会话会相互遮挡；三栏工作台可扩展，但小屏阅读面积不足；最终选择「待办侧栏 + 单一回复画布」，提供独立聚焦模式。默认没有仪表盘、数据大卡片和欢迎横幅。

```text
┌─────────────────────────────────────────────────────────────┐
│ 回合                                      聚焦 / 切换主题     │
├────────────────┬────────────────────────────────────────────┤
│ 待回复 / 已处理 │ 来源、项目、连接状态                         │
│ 搜索           │                                            │
│                │ 需要你决定的问题                            │
│ 请求一         │ 上下文 / 可折叠长内容 / 代码                  │
│ 请求二         │                                            │
│ 请求三         │ 单选 / 多选 / 自由回答                        │
│                ├────────────────────────────────────────────┤
│ 本机连接       │ 回复草稿、附件                               │
│ 隐私与设置     │ 暂存待办                  发送回复 ⌘↵         │
└────────────────┴────────────────────────────────────────────┘
```

所有任务信息左对齐；主阅读区域最多 76ch；问题区单独滚动，回复区始终可达。窄屏改为列表/详情两级导航，不挤成三列。聚焦模式只收起侧栏，不改变请求状态。

## 2. 视觉 token

基础色六个，不以彩色区块代替信息层级：

| 名称 | 亮色 | 用途 |
|---|---|---|
| 雾白 | `#F4F6FA` | 窗口底色 |
| 纸白 | `#FFFFFF` | 阅读画布 |
| 墨蓝 | `#20283D` | 主文字 |
| 石板 | `#606B80` | 次级文字 |
| 靛蓝 | `#4159C6` | 唯一主操作、焦点、选中 |
| 雾线 | `#DCE1EB` | 分隔、输入边界 |

语义扩展：成功 `#256B54`、警示 `#865600`、错误 `#AD3544`。状态必须同时有文字/图标，不仅依赖颜色。

暗色：底色 `#171C2B`、画布 `#202739`、文字 `#ECF0FA`、次级 `#AEB8CE`、强调 `#B5C1FF`、边界 `#3D4963`。暗色主按钮采用浅靛蓝底和深墨蓝文字，不机械反转亮色。对比度以实测为准，正文至少 4.5:1，控件边界及焦点至少 3:1；低对比装饰线不能单独标识输入框。

字体：macOS 使用系统 SF / 苹方；Windows 使用 Segoe UI / 微软雅黑；Linux 使用可用系统中文字体。不要在线字体请求。代码使用 SF Mono / Menlo / Consolas。标题 28/36、区标题 18/28、正文 15/26、操作 14/20、辅助信息 12/18；中文主体不以 11px 密集排版。600 字长消息必须实测阅读。

间距为 4、8、12、16、24、32、48；文本区左右 40，紧凑窗 24，窄屏 20。输入框圆角 12、选项 10、小徽记 6；不用所有块都同样圆角和阴影。只给浮层轻阴影。触控目标至少 44×44，纯桌面密集项也不低于 32×32。

## 3. 核心交互

### 收到请求

1. 后台记录请求后发出一次系统通知；默认不抢焦点、不置顶、不反复响铃。
2. 列表显示客户端名称、项目、问题摘要、等待时长；名称由连接元数据与本地配置共同组成，客户端自报名称标为自报，不冒充已认证身份。
3. 点击通知定位原请求。重复收到同一协议请求不得创建另一张卡。
4. 收到新任务不替换正在编辑的任务。列表顶部可提示“有新请求”，不移动当前焦点。

### 理解与回答

- 顶部首先回答「谁在问、在哪个项目、现在还能不能送达」。标题由明确字段提供或安全截断正文，不擅自生成影响语义的 AI 摘要。
- 消息支持安全 Markdown、代码、表格、附件。长代码折叠并有明确展开按钮；不能把关键问题藏在折叠区。
- 单选用 radio，多选用 checkbox，自由文本为独立输入。不从“是/否”的文字猜选项类型；旧 `zhi` 兼容模式保留原有多选语义，新协议明确 selection_mode。
- 用户输入按请求 ID 保存；切换任务不丢草稿。保存失败要显示，不能继续显示“已保存”。
- 附件是有稳定 ID 的独立对象，删除只更新一个状态源。显示真实类型、尺寸、文件大小；超限说明怎样处理。
- 回复编辑器默认纯文本；不增加第二套富文本编辑系统。Enter 换行，⌘/Ctrl+Enter 发出；中文输入法 composition 期间禁止触发提交。
- 发送前将选项、文字、附件合成固定快照，进入发送中后禁止重复提交。没有选择、文字或附件时不能发送；兼容“继续”必须是明确可见的选项，不塞入隐藏提示词。

### 三个不混淆的结果

| 操作 | 用户看到什么 | 系统语义 |
|---|---|---|
| 稍后处理 | 草稿已保留，任务仍待回复 | 不回应 MCP、不取消、无催促倒计时 |
| 发送回复 | 先“正在发送”，再显示真实送达阶段 | 回复内容快照；发送失败保留草稿 |
| 拒绝请求 | 对话框确认“向调用方返回拒绝” | 明确的否定结果；与关闭窗口不同 |

关闭窗口默认收起到后台，不默认为拒绝。主动退出且仍有请求时提示数量、退出影响；退出不能隐式同意。客户端取消会终止等待，旧草稿可查看但不能再发给新会话。

### 长时间等待与断线

默认允许等待 24 小时，实际受 MCP 客户端超时能力约束。界面显示经过时长，不制造紧迫倒计时。超时、断线、没有回复都不是同意。

连接断开：保留草稿，明确显示“调用方已断开，回复尚未送达”；禁用向旧连接提交，提供复制草稿。v0.1 不宣称跨客户端重启恢复原 MCP 请求。新请求必须明确建立关联才能带入旧草稿，不能自动重放。

## 4. 关键状态与文案

| 场景 | 标题/提示 | 可用动作 |
|---|---|---|
| 空列表 | 暂时没有待回复请求 | 查看本机接入说明 |
| 离线 | 调用方已断开；草稿仍在本机 | 复制草稿、查看连接 |
| 正在发送 | 正在把回复交给连接进程 | 不允许重复发送 |
| 写入 MCP 管道 | 已交给调用方连接，处理结果未知 | 查看本次回复 |
| 失败 | 回复未送出，草稿已保留 | 在有效连接上重试 |
| 已取消 | 调用方取消了这条请求 | 查看草稿、归档 |
| 过期 | 请求已结束，未向调用方表示同意 | 查看草稿 |
| 数据存储失败 | 草稿尚未保存，请先复制内容 | 复制、重试保存 |

协议无应用级 ACK 时不能显示“AI 已执行”。历史列表保留回复快照和投递阶段，不能用成功绿色抹平未知状态。

## 5. 键盘、无障碍与窗口

- Tab 顺序为导航 → 上下文 → 选项 → 编辑器 → 附件 → 操作。聚焦按钮有可见 3px 焦点环。
- Escape 关闭最上层非破坏浮层，不取消请求。弹窗焦点限制在内部，关闭恢复到触发按钮。
- 屏幕阅读器可获知选中请求、必填、附件移除、保存与送达状态；使用语义 HTML 和有界 live region。
- 系统缩放 200%、亮暗模式、减少动态效果、中文/英文混排分别检查。动画只用于状态反馈，100–160ms；reduced-motion 下关闭。
- 主窗建议 1120×780，最低 760×560；聚焦窗建议 640×760；更窄浏览器原型仅用于压力验证，不承诺移动端产品。
- OS 标题栏、拖拽区域、窗口阴影由桌面外壳负责；不绘制假红黄绿窗控。

## 6. 设计自查与原型边界

自查后移除了首页统计卡、渐变背景、装饰性大数字、三列工作台。保留一个精简回合图标、左侧队列与右侧稳定回复区。设计特点来自长等待和多项目任务的真实需求，而非给普通聊天界面换色。

本轮原型覆盖：任务切换、草稿、单选/多选、主题、聚焦、稍后、明确拒绝、模拟发送、历史、窄屏。使用演示数据；没有真实 MCP、原生通知、数据库、密码库或安全 Markdown 渲染器。原型的浏览器存储仅作演示，不是正式隐私存储方案。
