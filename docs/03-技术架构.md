# 03 · 技术架构与决策

状态：建议采用，需 M0 技术试验确认；不是性能测试结论。目标是减少并发与状态错误，不追逐“最新技术”标签。

## 1. 技术选型

| 层 | 方案 | 为什么 | 不选的方案 |
|---|---|---|---|
| 桌面外壳 | Tauri 2 / 系统 WebView | 沿用 Rust 能力，避免每实例带 Chromium；跨平台窗口与系统集成 | Electron 并非不行，但本产品无必要为统一 Chromium 付驻留成本 |
| 前端 | Vue 3、TypeScript strict、Vite | 状态/表单复杂度适中；与旧项目知识衔接，重写不等于换 React | 不用 Next.js/SSR，桌面静态界面不需要服务端渲染 |
| 界面基础 | CSS tokens + 语义 HTML + 经评估的无障碍无样式组件 | 可控制排版，又不手写复杂焦点算法 | 不全盘引入大型后台 UI 库；也不自研所有弹层/菜单 |
| 核心 | Rust、Tokio、固定版本 MCP SDK | 集中处理生命周期、校验和并发；stdio 桥接与 UI 分离 | 不跟随 SDK 的浮动 Git main |
| 数据 | SQLite，单写入口，版本化迁移 | 请求/草稿/投递记录需要事务；按需 WAL 和忙等待策略 | 不再多个进程各自覆盖一份 JSON；不引入 Postgres |
| 凭据 | 系统 Keychain / Credential Manager / Secret Service | 不把 token 写进普通配置和日志 | 不用前端 localStorage 保存生产敏感数据 |
| 测试 | Rust 单元/集成、前端 Vitest/组件测试、浏览器自动化、原生冒烟 | 覆盖协议、UI 与真实外壳不同边界 | 不用“打包成功”代表端到端通过 |

具体版本在 M0 查官方发布、兼容与安全公告后精确锁定；提交 Cargo.lock 与 pnpm-lock.yaml。重大升级单独验证，不自动以 registry latest 替换全部依赖。当前规划不承诺某个未来版本号。

## 2. 进程结构

```text
AI 客户端 A ──stdio── turndock-mcp A ─┐
AI 客户端 B ──stdio── turndock-mcp B ─┼─ 本机受保护 IPC ─ TurnDock 桌面进程
AI 客户端 C ──stdio── turndock-mcp C ─┘                    │
                                                请求协调器 / 单写入口
                                                   │          │
                                                SQLite    附件目录
                                                   │
                                              Tauri 命令/事件
                                                   │
                                             Vue 收件箱 / 聚焦窗
```

桌面进程承载本地协调器，无独立常驻系统服务。stdio 桥接器不依赖 Tauri/WebView；每个客户端一个桥接进程，多个调用共享桌面队列。桌面未运行时，桥接器通过平台启动入口启动受信任已安装应用，并等待有界握手；绝不从调用方传来的任意路径执行程序。

单实例争用必须有进程级锁与握手重试；第二个启动者只激活现有实例。桌面重启会让现有桥接调用进入断线/不可恢复结果，首版不承诺无缝保活；保存的请求留作历史，不能伪装仍在线。

macOS/Linux 采用用户私有目录内 Unix domain socket（目录 0700、socket 权限、对端身份检查）；Windows 使用有当前用户 ACL 的 named pipe。没有公网端口、HTTP API、固定裸 token。握手包含版本与实例随机值，防止陈旧 socket 误连；同用户已完全被攻陷不属于可由本产品隔离的攻击边界。

## 3. 代码边界（实施时创建）

```text
apps/desktop/             Tauri 外壳、窗口/托盘/通知、UI 命令
apps/frontend/            Vue 视图、设计 tokens、组件、视图状态
crates/domain/            请求/回复类型、纯状态机、不依赖 Tauri
crates/storage/           SQLite 迁移、事务、附件存储
crates/broker/            协调器、会话映射、本机 IPC
crates/mcp-bridge/        stdio MCP、能力协商、兼容 zhi、取消转发
crates/contracts/         可序列化协议类型、版本、前端类型生成
tests/fixtures/           脱敏请求、畸形 Markdown、图片、协议轨迹
tests/e2e/                假客户端、跨进程、崩溃/恢复、界面回归
```

不是微服务；最初可在同一 workspace 内逐步拆清边界。domain 不能调用 UI/数据库；前端只能通过 contracts 请求动作，不直接改数据库或拼接协议文本。业务状态在 Rust，前端保存暂态交互；避免两套状态机相互猜测。

## 4. 并发与一致性

- 协调器使用有界消息队列，数据库写入事务化；SQLite I/O 不阻塞 Tokio 协议处理线程。避免跨 await 持有全局锁。
- 全局 request_id 与 `(connection_instance, json_rpc_id)` 独立；JSON-RPC ID 只在对应连接命名空间有效。
- UI 提交带 request_id、revision、submission_id；重复 submission_id 返回同一个提交结果，不生成第二条回复。不同提交争用用 CAS/事务拒绝后到者。
- 取消与提交同时发生，由事务接受顺序决定唯一结果；一旦取消先提交，后续回复不能送出。已经写入管道的回复无法撤回，应如实记录。
- 列表订阅带递增 revision，事件丢失后重新取快照；别靠前端收到每一个事件保证正确性。
- 默认每连接 8 个待处理、全局 64 个，超出返回明确容量错误；这是初始安全上限，M0 压测后调整。已结束历史分页，不把所有附件和全文加载到列表。

## 5. 安全边界

外部 Markdown、文件名、客户端名称、路径、选项标签都是数据。HTML 默认禁用；渲染后按白名单清理；禁止内联事件、javascript/data 可执行链接、远程图片自动加载。代码块按需加载语言，不注入任意 HTML。

CSP 设置为本地脚本/样式与明确资源来源，不使用宽泛 unsafe-eval。原型 CSS 和生产配置不同；正式 Tauri 配置须在构建产物中验证。调用方内容不能访问系统命令。按窗口收窄 capabilities，并在每个 Rust 命令校验输入、请求状态与权限；自定义命令是否受能力约束必须实测，不能仅写一份 capability 文件就认为安全。

消息视图不提供文件系统或 shell 权限；文件选择/打开链接通过最小 Rust 命令，限制协议和目标。用户选择的文件读取后存入受管理附件目录，不保存可任意读取的外部路径。默认关闭内容遥测，日志只含脱敏 ID/状态/耗时，不含正文、图片、token。

## 6. 发布与升级

正式发布使用系统代码签名/公证和签名更新。桌面与桥接器同一版本包内交付；稳定启动路径指向已安装 bundle 中匹配桥接器。握手拒绝不兼容协议主版本。不能只替换 UI 二进制而留旧 MCP。

升级前不强杀等待任务：提示待处理数量，可等待队列清空或用户显式结束。下载先验签，安装保留上一版本；数据库迁移前检查恢复策略，不宣称可任意降级。Homebrew 管理安装与应用内更新明确互斥/分流，不覆盖包管理器文件。

M4 分别验证安装中断、签名损坏、空间不足、启动失败、旧桥接器、数据库新旧版本。首版若做不到可靠自更新，发布签名安装包和手动更新步骤，不自制不验证的下载替换器。
