# 03 · 技术架构

## 1. 进程结构

```text
Claude Code ─stdio─ turndock-mcp ─┐
Codex       ─stdio─ turndock-mcp ─┼─ Unix socket（0700 目录 + 对端 UID 校验）─┐
Cursor      ─stdio─ turndock-mcp ─┘                                           │
                                                                              ▼
                                         TurnDock.app（单实例）
                                         ├─ Broker：协调器 actor（唯一写入者）
                                         │    ├─ SQLite（请求、回复、草稿、附件）
                                         │    └─ IPC 服务
                                         ├─ Markdown 渲染与净化（Rust）
                                         └─ Tauri 窗口：收件箱 / 快速面板（Vue）
```

- **bridge（`turndock-mcp`）**：每个 MCP 客户端启动一个，只做协议转换。不依赖 Tauri/WebView，空闲内存目标 ≤ 10MiB。
- **broker**：一个库 crate，桌面应用把它嵌在进程里运行；测试和无界面开发时由 `turndock-broker` 独立运行。
- **找不到 broker 时**：bridge 用 bundle ID 让系统启动已安装的 TurnDock（macOS `open -g -b`，不执行调用方给的路径），最多等 8 秒。仍连不上就立即返回可读的错误，不要一直挂到宿主超时。
- **单实例**：tauri-plugin-single-instance，再加 socket 握手：第二个实例只激活已有窗口。

## 2. 选型（版本锁定在 Cargo.lock / pnpm-lock.yaml）

| 层 | 选择 | 理由 |
|---|---|---|
| MCP | `rmcp` 3.6（官方 Rust SDK），精确版本 | 支持取消（RequestContext.ct）、progress、instructions |
| 异步 | `tokio` | — |
| 存储 | `rusqlite`（bundled）+ 内建迁移表 | 同步 API 配合 actor 单写入者，比 sqlx 简单；WAL |
| Markdown | `pulldown-cmark` → `ammonia` 白名单净化 | 安全边界只有一处，前端不带 Markdown 库 |
| 图片校验 | `infer`（文件签名）+ `image`（解码尺寸） | MIME 以字节为准 |
| 类型共享 | `ts-rs` 从 Rust 导出 TS 类型，CI 检查是否最新 | 前后端只有一份契约 |
| 桌面 | Tauri 2.12（稳定线，不用 3.0 alpha） | 系统 WebView，驻留成本低 |
| 前端 | Vue 3.5 + TypeScript strict + Vite | 状态复杂度适中；无大型 UI 库 |
| 浮层 | 原生 `<dialog>`；复杂菜单需要时再引入 Reka UI | 少依赖 |
| 测试 | cargo test（状态机、竞态、IPC、端到端 MCP）、Vitest | 见 05 |

## 3. 代码结构

```text
crates/
  turndock-core/     领域类型、请求状态机、输入校验、IPC 帧定义；不依赖 IO
  turndock-broker/   协调器 actor、SQLite、IPC 服务、Markdown 渲染；bin: turndock-broker（无界面开发用）
  turndock-bridge/   bin: turndock-mcp（rmcp stdio 服务 + IPC 客户端）；端到端测试
apps/desktop/
  src/               Vue 前端（generated/ 为 ts-rs 导出的类型）
  src-tauri/         Tauri 外壳：嵌入 broker、命令、事件、通知、快捷键、托盘
docs/                设计文档
```

## 4. 并发与一致性

- **协调器是唯一的状态所有者**。它运行在独立线程的单线程 tokio 运行时上，按顺序处理命令：IPC 请求、UI 动作、计时器。所有竞态（提交 vs 取消、超时 vs 回复）都由处理顺序裁决，不靠锁。
- **先落库再生效**：每个状态变更先在 SQLite 事务里写入，成功后才更新内存和通知调用方。写失败则拒绝该动作并告知 UI。
- **UI 不维护第二套生命周期**：UI 拿到的是快照 + 单调递增的 revision；收到“已变化”事件后重新拉取。丢事件不影响正确性。
- **提交幂等**：UI 提交携带 submission_id；重复的 submission_id 返回同一结果。
- **容量**：每连接最多 16 条进行中请求，全局 256 条，超出返回明确错误。

## 5. 安全边界

- **IPC**：socket 在 `~/Library/Application Support/TurnDock/run/`（目录 0700）；accept 后校验对端 UID 与当前用户一致；握手带协议版本，主版本不同直接拒绝。没有网络端口。
- **内容**：调用方传来的消息、选项、名称都是数据。Markdown 在 Rust 中渲染后由 ammonia 净化：禁用原始 HTML 的脚本与事件属性，链接只允许 http/https/mailto，不渲染远程图片。前端只把净化后的 HTML 放进专用容器。
- **CSP**：`default-src 'self'; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'; script-src 'self'`，不使用 unsafe-eval。
- **Tauri 能力**：窗口只开放本应用的命令与必要插件；打开链接走 Rust 命令，只允许 http/https。
- **日志**：只记录 ID、状态、耗时，不记录正文、图片或路径之外的内容。

## 6. 发布

- 桌面应用与 bridge 在同一 bundle 内一起签名、一起升级；握手拒绝不兼容的主版本。
- 首版提供签名、公证的安装包和手动更新；自动更新只采用 Tauri updater 的签名验证方案，不自制下载替换。
- 与寸止可以并存；迁移工具只生成新的配置片段，由用户确认后再修改客户端配置。
