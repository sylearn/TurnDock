# 04 · 协议、状态与数据契约

本文件是实现约束草案；尚无可运行服务。M0 将其变为 Rust 类型、JSON Schema 与兼容性测试。

## 外部工具

保留 `zhi`：输入 `message`、`is_markdown`、`predefined_options`。兼容适配器需使用原项目/实际客户端的输出 fixture 校验内容块结构、图片编码、错误与取消，不凭工具名字相同宣称完全兼容。旧多选语义保留。适配器不添加隐藏增强词。

新工具暂定 `ask_user`，核心字段如下：

```json
{
  "title": "确认导出内容",
  "message": "报告已生成，请选择本次导出范围。",
  "format": "markdown",
  "selection_mode": "single",
  "options": [
    {"id": "summary", "label": "只导出摘要"},
    {"id": "full", "label": "导出完整报告"}
  ],
  "allow_text": true,
  "allow_images": true
}
```

`selection_mode` 为 none/single/multiple；无选项必须 none；single 最多一个。ID 唯一，选项由服务端校验，不能接受调用方集合外的选择。用户文本、选择、图片至少一项有效才可提交。`allow_*` 为输入约束，不允许界面暗自放宽。

初始限额：message UTF-8 256 KiB、title 160 字符、选项 32 个且每项 500 字符；图片最多 4 张、单张原始 10 MiB、单请求合计 20 MiB、解码像素上限 24MP。限额是设计值，M0 用目标客户端消息上限校准；响应 base64 体积也必须预估。超限拒绝并解释，不静默截断关键内容。拒绝 SVG/可执行内容，依据文件签名和实际解码确认 MIME。压缩需显示变更，不偷偷改文件类型。

新工具正常结果包含 `outcome: answered | declined`、稳定 `request_id`、`selected_ids`、`text`，图片通过 MCP 内容块返回并保留真实 MIME。传输失败、容量错误、输入无效与用户明确拒绝分开。不得用“用户拒绝”掩盖后端错误。

默认普通 stdio 工具调用长等待。若以后采用 MCP tasks，先协商客户端 capability、单独测试 tasks/cancel；首版不把新版可选能力当作所有宿主已支持。

## 身份与超时

桥接器为每次启动生成 connection_instance；broker 生成 request_id；调用方自报 name/project 只作展示。用户可配置本地可信标签。不要把任意工具参数中的项目路径当作授权读取目录。

默认等待上限 24 小时；客户端可能更早超时。持续时间以单调时钟判断，显示时间另存 UTC。心跳只用于连接活性，不等于延长宿主工具超时，也不制造虚假进度。超过等待上限明确终止并记录过期，绝不自动选择或假定同意。

## 状态机

```text
received → waiting → submitting → handed_off
              │          ├→ failed（有效连接上可显式重试）
              │          └→ delivery_unknown（不能盲目重发）
              ├→ cancelled（调用方取消）
              ├→ expired（超时）
              └→ disconnected（连接结束）
```

`answered/declined` 是回复内容的决定，不是投递状态。稍后处理不是协议状态变化，只更新界面排序/草稿。关闭窗口不改变 waiting。

`handed_off` 最多表示桥接器确认结果已写入 MCP 输出并完成相应 flush；没有上层确认时不表示客户端已读取或 AI 已执行。broker 先持久化提交快照，再通知桥接器；桥接器报告写出阶段。写出后 ACK 丢失，必须进入 delivery_unknown，不能自动重投。标准 MCP 不支持本产品保证跨进程崩溃的 exactly-once 消费。

提交与取消竞态使用同一状态机/事务仲裁。取消先到则不发回复；回复已实际写出后才取消，则记录竞态并停止后续动作，不能声称撤回成功。取消处理不等待用户关闭窗口。

## 持久化草案

| 表 | 核心字段 | 约束 |
|---|---|---|
| connections | instance_id、client_label、protocol、last_seen | 每次连接独立，不重用旧 session |
| requests | id、connection_id、rpc_id、state、revision、created_at、deadline、message | `(connection_id, rpc_id)` 唯一；状态 CAS |
| drafts | request_id、text、selected_ids、revision、saved_at | 每请求一个草稿；保存失败可见 |
| attachments | id、request_id、mime、bytes、digest、managed_path | 不存任意系统路径；对象只被一个写入口管理 |
| submissions | id、request_id、payload_snapshot、outcome、delivery_stage | submission_id 幂等；每请求最多一个有效终局决定 |
| events | sequence、request_id、kind、timestamp、redacted_detail | 不复制正文；有界保留 |
| preferences | key、value、schema_version | 非敏感偏好；凭据另存系统凭据库 |

事件表用于诊断，不把系统设计为完整 event sourcing。首次安装就有 schema_version 和迁移测试。SQLite 非透明加密存储：本地账号/磁盘加密是基础保护，不承诺数据库本身不可读取。

## 数据保留与用户控制

默认草稿随待处理请求保留；结束后正文、回复与附件保留 7 天，可设为不保留或 30 天。未处理内容不由后台静默清除；超出磁盘预算暂停新附件并说明。删除历史包括数据库正文、回复、附件与关联缩略图；外部导出文件不自动删除。日志不含正文，避免“删历史但日志还在”。

首次启用说明保留策略，设置提供清理预览。导出由用户显式触发，默认脱敏。无远程同步、无后台上传源码。未来凭据或 Telegram 功能另行征得接入授权。

## 必须有的协议 fixture

普通文字、空/多选、重复 option ID、JPEG/PNG、超限图片、HTML 事件、两客户端相同 RPC ID、并发请求、取消先到/回复先到、重复提交、写出后断电、24 小时等待、宿主提前超时、桌面重启、桥接版本不匹配。每个 fixture 固定输入、预期状态、输出与禁止发生的副作用。
