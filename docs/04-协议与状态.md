# 04 · 协议与状态

## 1. 核心思想：请求不随工具调用结束

宿主对单次工具调用有超时（Codex 默认 60 秒）。因此回合把**请求**和**等待它的调用**分开：

```text
AI ──ask_user/zhi──▶ 创建请求 R，调用挂起等待
                      │ 用户在等待预算内回复 ──▶ 返回回复
                      │ 等待预算用完 ──▶ 返回 pending(request_id=R)
AI ──await_reply(R)──▶ 再次挂起等待 …（可重复）
```

- 请求 R 一直留在 broker，直到用户回复、拒绝、关闭，或 AI 取消、过期。
- 用户在 AI 没有挂着调用时回复：回复保存为“待领取”，下次 `await_reply(R)` 立即拿到。
- request_id 是随机 UUID，起能力令牌的作用：AI 显式提供它，才能领取回复（可以来自新的连接，比如宿主重启后）。

## 2. 工具

### `hand_off`（回合交接，主场景）

做了实际工作的一轮结束前调用。纯问答不调用。

```json
{
  "title": "导出模块完成，CSV 与 JSON 均可用",
  "summary": "新增 `src/export.rs`；大于 50MB 的数据改为流式写出……",
  "checks": [
    {"label": "单元测试", "status": "passed", "detail": "54/54"},
    {"label": "1GB 以上大文件", "status": "not_run"},
    {"label": "Excel 打开中文 CSV", "status": "manual"}
  ],
  "risks": ["CSV 默认无 BOM，旧版 Excel 可能乱码"],
  "next_steps": [
    {"id": "bom", "label": "给 CSV 加 BOM 并补兼容测试", "reason": "唯一需要人工确认的风险，改动小", "recommended": true},
    {"id": "atomic", "label": "改为临时文件 + 原子重命名", "reason": "避免半个文件，约半小时"}
  ]
}
```

- `title`、`summary`、`next_steps` 必填；`next_steps` 1–6 个（建议 2–4），最多一个 `recommended`。
- `checks.status`：`passed` 已运行通过、`failed` 已运行失败、`not_run` 没有运行、`manual` 需要人来看。
- 验证最多 12 项，风险最多 8 项，每项不超过 500 字符。
- 界面预选推荐项；用户可改选、补充文字或图片，或选择“先停下”（outcome 为 declined）。
- 回复文本告诉 AI 选定的下一步与补充要求，并提醒它这一轮结束时再交接；`structuredContent` 与 `ask_user` 相同。

### `zhi`（寸止兼容）

参数与寸止一致：`message`（必填）、`predefined_options: string[]`、`is_markdown`（默认 true）。选项为多选语义。回复文本格式与寸止一致：

```text
选择的选项: 选项A, 选项B

用户输入的文字
```

图片作为 MCP image 内容块返回，MIME 与实际字节一致。不再在文本里附带 base64 预览。

### `ask_user`

```json
{
  "title": "确认导出范围",
  "message": "报告已生成，请选择本次导出范围。",
  "format": "markdown",
  "options": [
    {"id": "summary", "label": "只导出摘要"},
    {"id": "full", "label": "导出完整报告", "description": "包含附录", "recommended": true}
  ],
  "selection": "single",
  "allow_text": true,
  "allow_images": true
}
```

- `selection`：`none | single | multiple`。有选项时默认 `single`；无选项时必须是 `none`。
- 选项 ID 唯一；回复只能选择集合内的 ID；最多一个 `recommended`。
- 返回 `structuredContent`：`{outcome, request_id, selected_ids, selected_labels, text, image_count}`，同时提供人可读的文本块。

### `await_reply`

`{ "request_id": "…" }`。继续等待同一请求，返回与 `ask_user` 相同的结构。

### 返回结果

| outcome | 文本给 AI 的含义 |
|---|---|
| `answered` | 用户回复了：选项与文字 |
| `declined` | 用户明确拒绝（交接中为“先停下”）：不要执行；可附理由 |
| `pending` | 用户还没回复。**这不是同意。** 立即调用 `await_reply(request_id)` 继续等，不要结束回合，不要自行决定 |
| `dismissed` | 用户关闭了请求且没有回复。不要视为同意，停止相关操作并在对话中说明 |
| `cancelled` / `expired` | 请求已结束，未获得用户同意 |

错误（容量满、参数无效、broker 不可用）以 MCP 工具错误返回，并与用户的拒绝严格区分。

## 3. 等待预算

每次调用最多挂起 `wait`，在宿主超时之前返回 pending：

| 来源 | 默认 wait | 依据 |
|---|---|---|
| 环境变量 `TURNDOCK_WAIT_SECS` | 以此为准 | 用户最清楚自己的宿主配置 |
| Claude Code（`claude-code`） | 25 分钟 | 硬超时默认约 28 小时（`MCP_TOOL_TIMEOUT`），但 stdio 有 30 分钟空闲超时（`CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT`），没有响应或进度就会失败 |
| Codex（名称含 `codex`） | 50 秒 | `tool_timeout_sec` 默认 60 秒；建议在配置里调大，并同步设置 `TURNDOCK_WAIT_SECS` |
| 其他/未知 | 50 秒 | 保守值；M0 超时矩阵实测后按宿主调整 |

如果调用带 progressToken，等待期间每 20 秒发一次 progress（“等待用户回复”）。规范允许宿主据此重置超时，但不依赖它。

## 4. 状态机

请求有两个维度：**阶段（phase）** 与 **交付（delivery）**，另有当前挂着的调用 `attached`。

```text
phase:    waiting ──用户回复/拒绝──▶ decided
             ├──调用方取消（仅 attached 调用）──▶ cancelled
             ├──到达截止时间──▶ expired
             └──用户关闭──▶ dismissed

delivery（仅 decided）:
  pending（无调用挂着）──AI 领取──▶ in_flight ──bridge 确认──▶ handed_off
  in_flight ──连接断开、未确认──▶ unknown ──AI 再次领取──▶ in_flight
```

规则：

1. 同一时间只有一个调用挂在请求上；第二个 `await_reply` 返回“已有调用在等待”错误。
2. 预算到期：如果仍是 waiting，解除挂接并返回 pending；回复已在途时不再返回 pending。
3. 取消只对挂着的那个调用有效。waiting 时取消 → cancelled；回复已经 in_flight 时取消 → 不能撤回，记录竞态，状态以实际交付为准。
4. 连接断开：挂着的 waiting 请求只解除挂接（仍可被领取）；in_flight 变为 unknown。
5. `unknown` 时 AI 再次显式领取，说明它没拿到，可以重新交付。broker 永不主动重发。
6. broker 重启：waiting 请求保留（未挂接）；in_flight 变为 unknown。
7. 截止时间默认创建后 24 小时；dismissed、cancelled、expired 都不能转为 decided。

`handed_off` 表示 bridge 已把结果交给 MCP 运行时写出；没有应用层回执，不代表 AI 已读取或执行。

## 5. IPC 帧（bridge ↔ broker）

换行分隔的 JSON，每帧最大 32MiB。

```text
bridge → broker
  hello    {protocol: 1, bridge_version, client:{name,version}, cwd, pid}
  ask      {call, spec, wait_ms}
  await    {call, request_id, wait_ms}
  cancel   {call}
  ack      {call}                       // 结果已交给 MCP 运行时

broker → bridge
  welcome  {connection_id, broker_version}
  reject   {reason}
  created  {call, request_id}
  outcome  {call, request_id, result}
  error    {call, code, message}
```

`call` 是 bridge 内的递增编号，只在本连接内有效。

## 6. 持久化

| 表 | 关键字段 |
|---|---|
| `requests` | id、client_name、client_version、project、tool、spec_json、phase、delivery、decision_json、created_at、updated_at、deadline_at、revision |
| `drafts` | request_id、text、selected_json、updated_at |
| `attachments` | id、request_id、mime、bytes、width、height、data（BLOB） |
| `meta` | schema_version 等 |

- 时间用 UTC 毫秒；截止判断在运行时用单调时钟换算。
- 结束后的正文、回复与附件默认保留 7 天（可设为 0 / 30 天），未结束的从不自动清理。
- 日志不含正文，删除历史即删除全部内容。

## 7. 限额

| 项 | 限制 |
|---|---|
| message | 256 KiB（UTF-8） |
| title | 160 字符 |
| 选项 | 32 个，每个 label 500 字符 |
| 回复文字 | 64 KiB |
| 图片 | 最多 4 张；单张 10 MiB；合计 20 MiB；仅 PNG / JPEG / WebP / GIF，按文件签名判断 |

超限明确拒绝并说明原因，不静默截断。
