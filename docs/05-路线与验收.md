# 05 · 路线与验收

每一关都要有可运行的证据。上一关的风险没关闭，不扩展下一关的功能。

## M0 · 协议内核（无界面）

1. Rust workspace、锁定依赖、fmt / clippy / test。
2. `turndock-core`：请求状态机、输入校验、IPC 帧；单元测试覆盖第 4 节所有转换与随机竞态。
3. `turndock-broker`：协调器 actor、SQLite、IPC 服务（0700 目录 + 对端 UID）、Markdown 净化。
4. `turndock-mcp`：`zhi` / `ask_user` / `await_reply`，取消转发，等待预算，progress。
5. 端到端测试：真实启动 bridge 子进程，用 rmcp 客户端调用，验证回复、pending→续等、取消、断线后领取、两个连接隔离。
6. **宿主超时矩阵**：在用户实际使用的宿主上测默认超时、可配置项、progress 能否续期、取消行为，结果写入 04 第 3 节。

通过：竞态测试 1000 轮只有一个有效结局；断线、超时、取消都不产生“同意”；两个连接互不串线。

## M1 · 最小桌面闭环

1. Tauri 外壳嵌入 broker；收件箱显示真实请求；回复、拒绝、关闭。
2. 快捷回复（⌥1–⌥9）与快速回复面板；全局快捷键；通知；托盘计数。
3. 集成包：服务 instructions、规则片段、各宿主配置示例（含 Codex 超时设置）。
4. 接入用户的第一个真实宿主，录下端到端过程。

通过：A 类场景 3 次按键内完成；Codex 默认配置下离开 10 分钟回来仍能回复并被 AI 拿到。

## M1.5 · 自用替换（两周）

与寸止并行配置，作者每天实际使用。记录：每天交接与提问数、从交接到选定方向的耗时、接受推荐的比例、pending 续等次数、AI 交接质量问题（验证状态是否如实、建议是否具体）。用真实数据修正规则片段、工具描述和 M2 的设计。

## M2 · 完整回复体验

决策记录（按项目的交接时间线：选了什么、为什么）、图片随草稿持久化、键盘全流程、无障碍、200% 缩放、长消息性能、按宿主的提醒方式、退出时待回复确认。

通过：十条并行请求切换不丢草稿；输入法回车不发送；只用键盘能完成全部流程。

## M3 · 可靠性与隐私

故障注入（磁盘满、数据库忙、进程崩溃、系统睡眠）、历史保留与删除、依赖审计、真实 24 小时等待。

## M4 · 首个可安装版本

签名与公证、bridge 与应用同包、迁移向导（生成配置片段，用户确认后再改）、手动更新说明、干净机器安装测试。

## M5 · 有需求再做

Claude Code Stop hook 适配器、MCP tasks、Windows / Linux、远程回复。每一项单独做威胁模型与验收。

## 性能目标（release 构建，Apple Silicon）

| 指标 | 目标 |
|---|---|
| 新请求从 bridge 到界面可见 | p95 ≤ 150ms |
| 快速面板唤出到可输入 | p95 ≤ 120ms（应用已在运行） |
| 请求切换 | p95 ≤ 50ms（100 条历史、10 条待回复） |
| 空闲 CPU | < 0.5% 单核，无轮询 |
| 桌面驻留内存（含 WebView） | ≤ 150MiB |
| 每个空闲 bridge | ≤ 10MiB |
| 首屏 JS（gzip） | ≤ 80KiB |

## 发布阻断项

消息执行脚本；回复错投；沉默、取消或超时被当成同意；草稿静默丢失；MIME 与实际字节不符；“交付未知”被显示为成功；未验签的更新。任何一项未关闭都不能发正式版。

## 测试清单

| ID | 场景 | 期望 |
|---|---|---|
| P01 | 回复在等待预算内 | 返回 answered，状态 handed_off |
| P02 | 预算用完 | 返回 pending；await_reply 后拿到回复 |
| P03 | 无调用挂着时回复 | 状态待领取；下次 await 立即返回 |
| P04 | 调用方取消 | 状态 cancelled；之后的回复被拒绝 |
| P05 | 回复与取消竞态 1000 轮 | 恰好一个结局 |
| P06 | 回复在途时连接断开 | unknown；再次 await 重新交付 |
| P07 | 两个连接同时提问 | 各自只收到自己的回复 |
| P08 | 同一请求两个 await | 第二个返回错误 |
| P09 | 重复 submission_id | 返回同一结果，不产生第二次回复 |
| P10 | broker 重启 | waiting 请求仍可被 await 领取；正在等待的调用自动重连续等 |
| H01 | hand_off 往返 | 验证、风险、推荐项完整到达界面；回复写明选定的下一步 |
| H02 | hand_off 缺少下一步或多个推荐 | 参数错误，不创建请求 |
| S01 | Markdown 含 script / onerror / javascript: | 被净化，不执行 |
| S02 | 非本用户连接 socket | 被拒绝 |
| A01 | 伪造扩展名的图片 | 按签名判断类型或拒绝 |
| U01 | 输入法合成时 ⌘↵ / 回车 | 不发送 |
