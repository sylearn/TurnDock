## 2026-10-20 · 重新定位为“交接点”

依据：按请求计费已不是主流，记忆与代码检索有成熟的 skill / MCP。产品从“别让 AI 提前结束”转为“每一轮结束时的结构化交接”。详见 01。

### 已实现

- `hand_off` 工具：标题、做了什么、验证（passed / failed / not_run / manual）、风险、1–6 个下一步（最多一个推荐）。校验在 core，旧数据向后兼容。
- `ask_user` 选项支持 `recommended`。
- 回合卡界面：标题 → 验证 → 风险 → 下一步（推荐预选）→ 这一轮做了什么（长时折叠）；交接中隐藏快捷回复，“拒绝”改为“先停下”。
- 服务 instructions、工具描述、规则片段、默认快捷回复按新定位重写。
- 代码块语法高亮（syntect，配色进入设计 token）、复制按钮；标题去除内嵌 HTML；草稿保存状态误报修复。

### 已验证

- `cargo test --workspace` 66 项通过（新增 core 交接校验 3 项、bridge 格式 1 项、端到端 hand_off 往返与参数错误 2 项）；clippy 无警告。
- 预览截图：1080×820 窗口下标题、验证、风险、三个下一步均在首屏；亮暗两套配色检查。

### 未验证

- 真实 AI 在规则片段下的交接质量（是否如实标注 not_run、建议是否具体）需在 M1.5 自用中观察。
